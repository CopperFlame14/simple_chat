A Custom Application-Layer Protocol with Reliable Message Delivery

📋 Project Overview

Aim

To design and implement a custom application-layer communication protocol called Simple Chat Protocol (SCP) that enables reliable message exchange between a client and server using C programming language over TCP/IP sockets.

Objectives

  • Design a custom message format with protocol headers and data fields
  • Implement connection establishment and termination procedures
  • Create acknowledgment (ACK) mechanism for reliable delivery
  • Handle timeouts and retransmission logic
  • Demonstrate error handling and packet loss scenarios
  • Build interactive visualization to understand protocol behavior

Theory & Background

What is a Communication Protocol?

A communication protocol is a system of rules that allows two or more entities to transmit information. It defines:

  • Syntax: Structure and format of data (message format)
  • Semantics: Meaning of each section of bits (what each field represents)
  • Timing: When to send data and how fast (synchronization)

OSI Model Context

SCP operates at the Application Layer (Layer 7) of the OSI model, similar to HTTP, FTP, or SMTP. It uses TCP (Transport Layer) for underlying reliable communication.

Key Concepts in SCP

1. Message Format: Structured packets with version, type, ID, and payload
2. Acknowledgments (ACK): Server confirms receipt of each message
3. Timeouts & Retries: Client resends if ACK not received within timeout period
4. Connection Management: Proper setup (HELLO) and teardown (BYE) phases
💡 Learning Outcome: By implementing SCP, you understand how application protocols work at a fundamental level, including reliability mechanisms that protocols like TCP provide at lower layers.

❓ Help - How to Use SCP

Getting Started

Follow these steps to execute and use the Simple Chat Protocol project:

Step 1: Compile the Code

Use the provided Makefile or compile manually using GCC:

$ make

This will create two executables: scp_server and scp_client.

Step 2: Start the Server

In one terminal, run the server application:

$ ./scp_server

The server will start listening on port 8080 for incoming connections.

Step 3: Run the Client

In another terminal, run the client application:

$ ./scp_client

Follow the prompts to enter your name and connect to the server.

Step 4: Send Messages

Once connected, type your messages and press Enter to send them to the server.

The client will automatically handle acknowledgments and retransmissions if needed.

Step 5: Disconnect

Type "quit" to gracefully disconnect from the server and close the connection.

Correct Execution Flow

  1. Server starts and listens for connections
  2. Client connects and sends HELLO message
  3. Server acknowledges HELLO with ACK
  4. Client sends MSG messages
  5. Server acknowledges each MSG with ACK
  6. If ACK not received, client retransmits after timeout
  7. Client sends BYE message to disconnect
  8. Server acknowledges BYE and closes connection

Interpreting Results

The protocol simulator on this website demonstrates:

  • Message Flow: Shows how messages travel between client and server
  • ACK Mechanism: Displays acknowledgment messages confirming receipt
  • Timeout Handling: Illustrates what happens when acknowledgments are delayed or lost
  • Retransmissions: Shows how the protocol recovers from packet loss

Graph Interpretation

The protocol visualization shows:

  • Message IDs for tracking and correlation
  • Successful deliveries and retransmissions
